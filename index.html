Executive Summary

Data center cooling failures are costly and, by the time conventional software tools detect them, hardware damage may already be under way.

This project presents an independent, out-of-band telemetry platform that monitors the physical health of server cooling fans without consuming any resources on the host server.

An ESP32-S3 microcontroller running MicroPython captures fan vibration (MPU6050 accelerometer) and exhaust-aisle temperature (DHT22 sensor) and streams the readings as JSON over Wi-Fi to a Python 3 analytics server. The server applies Fast Fourier Transform (FFT) signal processing and an unsupervised Isolation Forest model to flag anomalies before they cause downtime, and presents results on a Streamlit dashboard.

1Introduction

1.1 Problem Statement

Data centers are the backbone of modern internet infrastructure. High-performance computing hardware inside a server rack runs continuously and generates substantial heat. If a primary cooling fan slows, develops bearing wear, or has its airflow path blocked, the server overheats, leading to thermal throttling (reduced processing speed) or complete hardware failure.

Traditional software tools monitor internal CPU temperatures but offer no predictive insight into the state of physical hardware. By the time a CPU reports an overheating error, component damage may already be occurring.

1.2 Proposed Solution

The project introduces an out-of-band physical telemetry platform. An independent ESP32-S3 microcontroller at the network edge monitors fan structural vibration and exhaust-aisle temperature. Work is divided across two components:

  • Edge client node: Runs optimized MicroPython, reads an MPU6050 accelerometer and a DHT22 climate sensor, and streams telemetry over local Wi-Fi.
  • Central analytics hub: Runs a native Python 3 server on an external laptop that performs digital signal processing and executes an unsupervised machine-learning model to flag anomalies.

3Hardware Architecture

3.1 Processing Core

The ESP32-S3 development board (N16R8 variant) was selected for three reasons:

  • Vector extensions: Built-in vector instructions accelerate matrix math and array processing.
  • Memory headroom: 16 MB of flash and 8 MB of PSRAM allow high-frequency sensor streams to be buffered without exhausting memory.
  • Integrated radio: Native 2.4 GHz Wi-Fi removes the need for external communication shields.

3.2 Multi-Sensor Array

Sensors are placed directly at server exhaust points to capture both mechanical and thermal changes.

  • MPU6050 (vibration): A 3-axis accelerometer and gyroscope. Degrading fan bearings wobble, producing small high-frequency structural vibrations that the sensor captures on the X, Y and Z axes.
  • DHT22 (thermal): A digital temperature and humidity sensor (±0.5 °C) placed at the hot-aisle exhaust vent. It detects thermal climbs caused by fan slowdown or blocked intake filters.

3.3 Pin Mapping

Pins were chosen to avoid boot-loop risks and conflicts with internal flash memory lines on the ESP32-S3 expansion base.

3.4 Assembly Best Practices

  • Soldering: Loose jumper connections introduce noise, so header pins should be soldered to the sensor breakout boards. A breadboard can serve as a soldering jig: seat the long ends of the male headers in a breadboard row, lower the sensor board over the short pins, and solder carefully.
  • Mechanical coupling: Loose tape dampens vibration and distorts acceleration data. Mount the MPU6050 to the chassis with a magnetic mount or rigid thermal epoxy to ensure clean vibration transfer.

4Edge Firmware

The edge system runs MicroPython, which executes a standard Python interpreter directly on the ESP32-S3 and allows rapid script updates through the Thonny IDE. Two components form the firmware foundation (full listings in Appendix A):

  • Initialization bus scan: At boot, the device scans the I2C bus to verify that peripherals are connected and responsive, and reports an error if none are found.
  • Hardware driver: An object-oriented MPU6050 class wakes the chip by writing to the power-management register (0x6B), reads 14 consecutive bytes starting at 0x3B, and converts the raw registers to signed two’s-complement integers.

5Distributed Network and Data Ingestion

Running machine-learning computation on a microcontroller can create bottlenecks and delay data collection. The workload is therefore split: the edge device handles acquisition only, while an external laptop performs analytics. The two communicate over local Wi-Fi using TCP sockets.

ESP32-S3 client (MicroPython)

  • Samples physical sensors
  • Bundles readings into JSON strings
  • Streams packets over a TCP socket

Laptop data server (Python 3)

  • Listens on network port 5001
  • Parses each JSON payload
  • Appends records to server_log.csv

The ingestion engine binds to all local network adapters, accepts connections from the edge node, and commits each telemetry record to a CSV file with the columns timestampaxayaztemphumidity

6Signal Processing and Machine Learning

6.1 Frequency Analysis with FFT

An active rack produces continuous background vibration. To extract meaningful patterns, time-domain acceleration data is converted into frequency spectra using the Fast Fourier Transform (SciPy). This makes fan harmonics visible: a stable fan produces a uniform frequency profile, while bearing failure or wobble produces high-frequency harmonic anomalies.

6.2 Anomaly Detection with Isolation Forest

Real fan failures occur unpredictably, making pre-labeled fault data difficult to obtain. The project therefore uses an unsupervised Isolation Forest (scikit-learn).

  • Method: The algorithm isolates points by random partitioning. Anomalies need fewer partitions to separate from normal operation.
  • Output: The model returns 1 for normal operation and -1 for a statistical anomaly, which triggers a maintenance flag.

7Telemetry Dashboard

A Streamlit web dashboard presents live operational metrics: exhaust-vent temperature, chassis humidity and the number of logged samples. It trains the Isolation Forest on acceleration and temperature features, displays a critical warning when the latest reading is anomalous, and charts the three acceleration axes over time.

10Conclusion and Future Scope

10.1 Accomplishments

The project demonstrates a low-power, distributed monitoring system for data center equipment. Separating tasks between an agile edge client and a central laptop server avoids using any production-server compute resources. The framework delivers real-time monitoring, unsupervised machine-learning insight, an interactive dashboard and organized version control, forming a clean blueprint for modern infrastructure tracking.

10.2 Future Enhancements

  • On-device TinyML: Optimize the isolation algorithm with compressed frameworks such as TensorFlow Lite for Microcontrollers so anomaly classification runs directly on the ESP32-S3.
  • Acoustic analytics: Add a microphone array (for example, MAX9814) to detect ultrasonic bearing squeals or airflow blockages before they produce vibration or heat.

A.2 MPU6050 Driver (MicroPython)

class MPU6050:
    def __init__(self, i2c, addr=0x68):
        self.i2c = i2c
        self.addr = addr
        self.i2c.writeto_mem(self.addr, 0x6B, b"\x00")  # wake from sleep

    @staticmethod
    def _signed(hi, lo):
        v = (hi << 8) | lo
        return v - 65536 if v > 32767 else v

    def get_raw_values(self):
        d = self.i2c.readfrom_mem(self.addr, 0x3B, 14)
        return {"ax": self._signed(d[0], d[1]),
                "ay": self._signed(d[2], d[3]),
                "az": self._signed(d[4], d[5])}

A.3 Ingestion Server (Python 3)

The edge client must terminate each JSON packet with a newline character.

import socket, json, csv, os

PORT = 5001
CSV_FILE = "server_log.csv"

srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
srv.bind(("0.0.0.0", PORT))
srv.listen(1)
print(f"[*] Listening on port {PORT}...")

if not os.path.exists(CSV_FILE):
    with open(CSV_FILE, "w", newline="") as f:
        csv.writer(f).writerow(["timestamp","ax","ay","az","temp","humidity"])

while True:
    conn, addr = srv.accept()
    print(f"[+] Connection from {addr}")
    with conn, conn.makefile("r", encoding="utf-8") as stream:
        for line in stream:
            try:
                p = json.loads(line)
                with open(CSV_FILE, "a", newline="") as f:
                    csv.writer(f).writerow([p["time"], p["ax"], p["ay"],
                                            p["az"], p["temp"], p["hum"]])
            except (ValueError, KeyError) as e:
                print(f"[-] Bad packet: {e}")

A.4 Frequency Analysis (Python)

import numpy as np
from scipy.fftpack import fft

def process_vibration_frequencies(samples, sampling_rate_hz):
    n = len(samples)
    yf = fft(samples)
    xf = np.linspace(0.0, sampling_rate_hz / 2.0, n // 2)
    amplitude = 2.0 / n * np.abs(yf[0:n // 2])
    return xf, amplitude

A.5 Streamlit Dashboard (Python)

import streamlit as st
import pandas as pd
from sklearn.ensemble import IsolationForest

st.set_page_config(page_title="Data Center Edge AI Dashboard", layout="wide")
st.title("Data Center Predictive Maintenance System")

try:
    df = pd.read_csv("server_log.csv")
    features = df[["ax", "ay", "az", "temp"]]
    model = IsolationForest(contamination=0.05, random_state=42).fit(features)
    df["anomaly_score"] = model.predict(features)
    latest = df.iloc[-1]

    st.subheader("Live Operational Matrix")
    c1, c2, c3 = st.columns(3)
    c1.metric("Exhaust Vent Temperature", f"{latest['temp']} °C")
    c2.metric("Chassis Humidity", f"{latest['humidity']} %")
    c3.metric("Logged Samples", len(df))

    if latest["anomaly_score"] == -1:
        st.error("Thermal or vibrational anomaly detected: possible cooling failure.")
    else:
        st.success("Operational metrics normal.")
    st.line_chart(df[["ax", "ay", "az"]])
except Exception:
    st.warning("Awaiting telemetry from the ESP32 client node...")
